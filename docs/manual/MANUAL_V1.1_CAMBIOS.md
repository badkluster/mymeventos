# Manual de Usuario M&M Eventos - cambios de la versión 1.1

Actualizado: 10 de agosto de 2026.

## Cambios incorporados

- Se eliminó `localhost` como dirección sugerida para usuarios finales y se reemplazó por la dirección de backoffice proporcionada por Administración.
- Se agregó un glosario básico para Lead, Pipeline, Staff, Briefing, RSVP y Adenda.
- Se agregó una síntesis de automatizaciones frecuentes del sistema.
- Se eliminó el workaround que pedía cambiar manualmente el evento a `Seña pendiente` después de aprobar un contrato.
- Se eliminó el workaround que pedía salir y volver a Pagos para ver un cobro recién registrado.
- Se documentó el comportamiento vigente: aprobación contractual sincronizada y actualización inmediata de pagos.
- Se actualizó el ciclo de Staff: Confirmado / Ingresó / Completado / Cancelado / Ausente y su relación con el Cierre Operativo.
- Se aclaró que Completado, Cancelado y Ausente son estados terminales aceptados para el cierre operativo.
- Se documentó que los formularios de proveedores actuales conservan rótulos visibles.
- Se amplió la explicación del Consolidado de Producción y la diferencia entre faltante contra stock y cantidad pendiente de elaborar.
- Se reemplazaron en la guía de bloqueos los dos bugs ya corregidos por instrucciones actuales de Staff y Cierre Integral.
- Se actualizó la versión del manual de 1.0 a 1.1.

## Capturas históricas

Algunas capturas fueron tomadas durante el relevamiento inicial y muestran la interfaz previa a correcciones posteriores. Cuando una captura ya no coincide exactamente con la UI actual, el manual lo indica expresamente y utiliza como fuente de verdad el comportamiento vigente descrito en el texto.

Para una próxima versión 1.2 se recomienda recapturar visualmente:

- Staff del evento con las nuevas acciones de ciclo de vida;
- alta/edición de proveedores con rótulos persistentes;
- contrato aprobado sin acción redundante Aprobar;
- cualquier pantalla donde se hayan consolidado traducciones de enums.
